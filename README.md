# نظام إدارة المدرسة للمعلمين

تطبيق Flutter مخصص للمعلمين لإدارة ومتابعة الأعمال اليومية داخل المدرسة من مكان واحد. يربط التطبيق بين واجهة عربية سهلة الاستخدام وواجهة برمجية Backend، ويتيح للمعلم متابعة الصفوف والطلاب والحضور والدرجات والجدول والأخبار والإشعارات والتواصل مع إدارة المدرسة.

> **حالة المشروع:** التطبيق يحتوي على واجهات ومكاملات API متعددة، ويحتاج إلى Backend يعمل ومتوافق مع المسارات الموضحة في هذا الملف حتى تعمل البيانات الحقيقية. لا يتم تضمين أي بيانات اعتماد أو أسرار داخل المستودع.

## المزايا

- تسجيل دخول للمعلم باستخدام رقم الهاتف وكلمة المرور.
- استعادة الجلسة تلقائيًا بعد إغلاق التطبيق.
- لوحة تحكم تعرض ملخص بيانات المعلم والإحصاءات المهمة.
- عرض الصفوف والشعب والطلاب التابعين لكل شعبة.
- تسجيل حضور الطلاب وتعديل الحالة وحفظها دفعة واحدة.
- عرض جدول اليوم والجدول الأسبوعي.
- عرض درجات الطلاب وإضافة الدرجة وتعديلها وحذفها.
- دعم مكونات المادة مثل الكتابي والشفهي والتطبيقي عند إدخال الدرجات.
- إضافة ملاحظات لأولياء الأمور وتعديلها وحذفها وإرفاق ملفات بها.
- عرض الأخبار والإعلانات مع عداد غير المقروء، وتحديد خبر كمقروء أو تحديد الكل كمقروء.
- فتح الصور والفيديو والروابط المرفقة بالأخبار.
- عرض الإشعارات في تبويبين: مقروءة وغير مقروءة، مع تحديدها كمقروءة أو حذفها.
- تقديم طلبات تبرير الغياب وتحديث حالتها وحذفها.
- عرض وتعديل الملف الشخصي للمعلم مع اختيار صورة شخصية.
- إرسال المقترحات والشكاوى ومراجعة التفاصيل السابقة.
- شاشة مساعدة لاستعادة كلمة المرور تعرض بيانات التواصل وساعات العمل.
- واجهة عربية من اليمين إلى اليسار مع حالات تحميل وفراغ وأخطاء وتحديث بالسحب في الشاشات المناسبة.

## المعمارية

يتبع المشروع تنظيمًا قريبًا من **Feature-first architecture**، بحيث تكون كل وظيفة داخل مجلد مستقل، وتنقسم غالبًا إلى:

1. **Data:** نماذج البيانات وRepositories المسؤولة عن الاتصال بالـ API وتحويل JSON إلى كائنات Dart.
2. **Presentation:** الصفحات وCubit وStates المسؤولة عن عرض البيانات والتفاعل معها.
3. **Core:** الخدمات المشتركة مثل الشبكة والتخزين والتنقل.
4. **Shared:** المكونات المرئية والثيم والمسافات والألوان المشتركة بين الشاشات.

تُسجل جميع Repositories وCubits في `main.dart` باستخدام `MultiRepositoryProvider` و`MultiBlocProvider`. هذا يفصل منطق البيانات عن الواجهة ويسهّل اختبار كل Repository بشكل مستقل.

## الشاشات والوظائف

### المصادقة والملف الشخصي

- **تسجيل الدخول:** يرسل بيانات المعلم إلى `/api/teacher/login`، ويعرض أخطاء التحقق القادمة من الخادم بجانب الحقول المناسبة.
- **استعادة الجلسة:** عند بدء التطبيق تتم قراءة رمز الجلسة من التخزين الآمن ومحاولة إعادة الدخول.
- **تسجيل الخروج:** يستدعي `/api/teacher/logout` ثم يحذف الرمز المحلي.
- **الملف الشخصي:** يجلب بيانات `/api/teacher/me`، ويدعم تحديث البيانات والصورة الشخصية عبر طلب multipart إلى `/api/teacher/profile`.
- **المساعدة:** يجلب معلومات الدعم من `/api/teacher/support` ويعرضها في نافذة منظمة من زر نسيان كلمة المرور.

### البيانات الأكاديمية

- **لوحة التحكم:** تعرض ملخص المعلم من `/api/teacher/dashboard`.
- **الصفوف والطلاب:** تعرض الشعب والطلاب والحضور المرتبط بكل شعبة من `/api/teacher/sections-with-students`.
- **الحضور:** تجلب الشعب والطلاب، تسمح بتغيير حالات الحضور، ثم تحفظ التعديلات دفعة واحدة عبر `/api/teacher/attendance/sections/{sectionId}/batch-update`.
- **الجدول:** تعرض جدول اليوم من `/api/teacher/schedule/today` وجدول الأسبوع من `/api/teacher/schedule/week`.
- **الدرجات:** تجلب درجات الطلاب من `/api/teacher/marks/students`، وتدعم الإضافة والتعديل والحذف وجلب مكونات المادة.
- **ملاحظات أولياء الأمور:** تدعم عرض الملاحظات وإنشاءها وتعديلها وحذفها، مع رفع مرفقات عبر multipart.

### الأخبار والإشعارات

- **الأخبار:** عرض الخبر ومرفقاته، فتح الصور، تشغيل الفيديو، وفتح الروابط؛ مع تعليم خبر واحد أو كل الأخبار كمقروءة.
- **الإشعارات:** جلب قائمة الإشعارات، عرض عدد غير المقروء، تعليم إشعار أو جميع الإشعارات كمقروءة، والحذف.

### التواصل والطلبات

- **طلبات تبرير الغياب:** عرض الطلبات وتحديث حالتها وحذف الطلب.
- **المقترحات:** إرسال مقترح بعنوان ومحتوى، وعرض القائمة والتفاصيل.
- **الشكاوى:** إرسال شكوى بعنوان ومحتوى، وعرض القائمة والتفاصيل.

## الاتصال بالـ Backend

يستخدم التطبيق `ApiClient` موحدًا لجميع الطلبات. عنوان الخادم الافتراضي هو:

```text
https://drab-alibda-sms.duckdns.org
```

يمكن تغيير العنوان بدون تعديل الكود باستخدام متغير البناء:

```bash
flutter run --dart-define=API_BASE_URL=https://example.com
```

يُرسل رمز الجلسة عادةً في ترويسة `Authorization`، وتُستخدم مهلة اتصال افتراضية مقدارها 15 ثانية. يدعم العميل JSON ورفع الملفات بصيغة multipart، ويطبع تفاصيل الطلب والاستجابة في وضع Debug فقط.

## متطلبات التشغيل

- Flutter SDK متوافق مع Dart `3.11.4` أو أحدث ضمن سلسلة Flutter الداعمة له.
- Android Studio أو Xcode حسب المنصة المستهدفة.
- جهاز فعلي أو Emulator/Simulator.
- Backend متاح ويقدم API المتوافقة مع المسارات السابقة.
- عند تشغيل Backend محليًا: PHP وLaravel، مع وجود ملف `artisan` في مجلد Backend.

## التشغيل

من مجلد المشروع:

```bash
flutter pub get
flutter run
```

لتشغيل نسخة مرتبطة بخادم محلي:

```bash
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000
```

`10.0.2.2` هو عنوان الجهاز المضيف من Android Emulator. على جهاز Android فعلي استخدم عنوان IP الخاص بجهاز الكمبيوتر على الشبكة نفسها، وتأكد من السماح بالاتصال عبر الجدار الناري.

### تشغيل Laravel محليًا على Windows

يوفر المشروع سكربتين جاهزين داخل `scripts/`:

```powershell
scripts\start_backend.ps1
```

أو:

```cmd
scripts\start_backend.bat
```

يمكن تحديد مسار Backend والمنفذ في PowerShell:

```powershell
scripts\start_backend.ps1 -BackendPath "C:\path\to\backend" -Port 8000
```

## الأمان ومعالجة الأخطاء

- يتم تخزين رمز الجلسة باستخدام `flutter_secure_storage` بدل تخزينه كنص عادي.
- لا تُطبع بيانات الطلبات الحساسة في نسخ Release؛ سجلات الشبكة مفعلة في Debug فقط.
- توجد معالجة لأخطاء Flutter والأخطاء غير المعالجة على مستوى التطبيق باستخدام `runZonedGuarded`.
- يعرض التطبيق حالات التحميل والفراغ وفشل الاتصال ورسائل التحقق القادمة من الخادم.
- يجب وضع مفاتيح الإنتاج وأي أسرار في إعدادات Backend أو متغيرات بيئة خارج المستودع.

## ملاحظات التطوير

- يجب أن يعيد Backend JSON بالبنية التي تتوقعها نماذج المشروع، خصوصًا بيانات الطلاب ومكونات الدرجات.
- عند تغيير عنوان API في بيئة جديدة استخدم `--dart-define` بدل تعديل العنوان الافتراضي داخل الكود.
- عند إضافة ميزة جديدة، يُفضل إنشاء مجلد Feature يحتوي على `data` و`presentation`، ثم تسجيل Repository وCubit في `main.dart`.
- لا تعتمد الواجهة على بيانات وهمية؛ نجاح الشاشات التي تعرض بيانات فعلية يتطلب تشغيل Backend وتسجيل دخول صحيح.
